## 목적

작업을 실제로 커밋하지 않고 **커밋 메시지 텍스트만** 만들어 보여 준다. 커밋 여부와 시점은 사용자가 정한다.
규칙의 배경은 `rules/git-commit.md`를 참고한다.

## 수행 순서

**1. 변경 범위 파악**
```bash
git status --short
git diff --stat
```
- 범위는 그 시점에 커밋되지 않은 변경 전체다. 사용자가 직접 고친 것도 포함한다.
- 필요하면 `git diff <파일>`로 실제 변경 내용을 확인해 메시지가 실제 코드와 어긋나지 않게 한다.

**2. 첫 줄 결정**
1. `.claude/current_issue.md`가 있으면 그 파일의 `commit_prefix` 값을 **그대로 첫 줄로 고정**한다.
2. 없으면 `git log --oneline -5`로 저장소 컨벤션을 확인한다. 이슈 링크 + 제목 형식을 쓰는 저장소라면 관련 이슈를 알 때만 그 형식을 따르고, 모르면 지어내지 않는다.
3. 이슈가 없고 저장소가 Conventional Commits를 쓰면 `<type>: <description>`(`fix:`, `feat:`, `refactor:` 등) 형식을 쓴다. 그 외에는 첫 줄 없이 `- ` 줄만 쓴다.

**3. 본문 작성**
- 구현한 내용만 `- `로 시작하는 줄에 하나씩 적는다.
- 큰 단위의 주요 변경만 3~5줄 정도로 추린다. 수치 조정 같은 자잘한 항목은 넣지 않는다.
- 설명, 배경, 사유 문장은 넣지 않는다.

**4. 출력**
- 코드 블록으로 감싸서 그대로 복사해 쓸 수 있게 준다.
- 메시지는 **하나만** 준다. 작업별로 나눈 대안 메시지를 덧붙이지 않는다.

예:
```
https://issues.example.com/browse/PROJ-123 위젯 테마 변경 시 갱신 처리

- 테마가 바뀌면 위젯 즉시 갱신
- 상세 화면 북마크 활성 색상을 시스템 primary로 변경
```

## 주의

- 사용자가 커밋을 명시적으로 요청하기 전까지 `git add`도 `git commit`도 실행하지 않는다.
