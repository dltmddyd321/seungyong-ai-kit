# 보안·배포 점검 규칙

1, 2번은 "직접 실행하지 말고 제안만" 한다. 실행은 사용자가 승인한 뒤에 한다. 3~5번은 작업을 맡겨 둔 상태에서도 지키는 멈춤 지점과 점검 항목이다.

## 1. 보안 경계에 닿는 작업이면 범위를 좁힌 보안 감사를 제안한다

보안 경계에 닿는 작업을 끝냈으면, 보안 감사 스킬(예: `security-audit`)로 범위를 좁힌 감사를 돌릴지 먼저 제안한다.

**Why:** 사용자가 "중요한 작업이면 판단해서 제안해 달라"고 요청했다. 전체 감사는 에이전트를 여러 개 띄워 토큰 비용이 커서 자동으로 실행하지 않는다.

**제안 대상**
- 딥링크, 외부 앱이나 브라우저에서 들어오는 진입점
- 외부에 노출된 컴포넌트, 엔드포인트
- 웹뷰, 외부 HTML 렌더링
- 인증 토큰, 로그인, 세션
- 결제, 구독
- 서버 API 인증·헤더
- 서명·빌드 설정. 예: 개발용 빌드가 운영 키로 서명되고 디버그가 켜져 있으면, 유출됐을 때 운영 앱 위에 설치될 수 있다.
- 파일 처리, 공유 처리
- 외부 입력 파싱

플랫폼별 구체적인 대상은 해당 폴더 규칙에 둔다(예: `android/rules/kotlin-android.md`).

**제안하지 않는 것**
- 순수 UI, 문구, 색상, 레이아웃
- 내부 로직 리팩터링

**제안 방식**
- 한두 줄로 쓴다. 왜 필요한지, 좁힌 범위(예: "이번 초대 링크 처리 경로만"), 비용을 함께 말한다.

## 2. 빌드 업로드·배포 전에는 release 전용 변환 점검을 제안한다

사용자가 빌드 업로드나 배포를 하려는 게 보이면 직접 실행하지 말고, release 빌드에서만 일어나는 변환(난독화, 코드 축소, tree-shaking, 번들 최적화)이 동작을 깨지 않는지 먼저 점검하자고 제안한다.

- 리플렉션이나 이름 기반 직렬화를 쓰는 코드가 가장 먼저 깨진다.
- 플랫폼별 점검 스킬이 있으면 그것을 쓴다(예: Android는 `android/skills/release-obfuscation-check`).

**Why:** 이런 문제는 release 빌드에서만 드러난다. 직렬화하던 클래스 이름이 난독화되어 release에서만 크래시가 난 사례가 있다.

## 3. 전권 위임을 받았어도 멈추는 세 가지

사용자가 "묻지 말고 끝까지 진행하라"고 맡겨 둔 저장소나 작업이라도 아래 세 가지는 실행 전에 확인을 받는다. 나머지(커밋, 푸시, PR, 머지 등)는 위임 범위 안에서 그대로 진행한다.

- **시크릿 노출:** API 키, 토큰, 서명 키나 인증서 비밀번호를 커밋, 로그, 대화, 공개 문서에 쓰게 되는 경우. 값은 셸 변수로만 다루고 화면에 출력하지 않는다.
- **되돌리기 어려운 작업:** force push, 히스토리를 고쳐 쓴 뒤의 push, 브랜치나 태그 강제 삭제, 보호된 브랜치 직접 push(저장소 규칙이 허용한 경우 제외).
- **외부에 영구히 공개되는 작업:** 저장소 공개 전환, 공개 저장소에 새 산출물 배포, 저장소 시크릿 변경이나 삭제.

**Why:** 위임은 속도를 위한 것이고, 위 세 가지는 한 번 일어나면 되돌릴 수 없거나 되돌려도 이미 퍼진 뒤다.

## 4. 저장소를 처음 공개하기 전에 점검한다

로컬에서 만들던 프로젝트를 원격 저장소에 처음 올리거나 공개로 바꾸기 전에 아래를 확인한다.

- 히스토리 전체에서 키 형태 문자열을 검색한다(`git log -p | grep -E '<키 접두어 패턴>'`). 값은 출력하지 않고 걸린 커밋만 본다.
- `.env`, 로컬 설정 파일, 서명 키와 인증서, 서비스 계정 JSON 같은 비밀 파일이 추적되지 않는지 본다.
- 빌드 산출물, 의존성 폴더(`node_modules/`, `venv/` 등), 내려받은 대용량 파일, 개인 사진이나 문서가 무시되는지 본다. `.gitignore`에서 `/build`처럼 앞에 `/`를 붙인 패턴은 루트 폴더만 잡고 하위 폴더의 같은 이름은 잡지 않는다.
- 첫 커밋 전에 `git diff --cached --stat`으로 파일 수와 크기를 훑는다. 예상보다 크면 멈추고 원인을 찾는다.
- 공개, 비공개 여부는 사용자가 정한다.

**Why:** `.gitignore`에 `/build`만 있어서 하위 폴더의 빌드 산출물 442MB가 첫 커밋에 들어갈 뻔했다. 스테이징 크기를 훑어서 푸시 전에 잡았다.

## 5. 배포 산출물에 비밀값을 넣지 않는다

남에게 나눠 주는 산출물(앱 설치 파일, 웹 프론트엔드 번들, 데스크톱 실행 파일, 컨테이너 이미지)에 들어간 키는 누구나 꺼낼 수 있다고 본다. 난독화나 빌드 설정 변수에 넣는 것으로는 숨겨지지 않는다.

- 외부 배포용은 키 없이 만들고, 키가 없으면 그 기능만 꺼지게 한다.
- 산출물을 만든 뒤 키 자리가 비었는지 확인한다. 값은 출력하지 않고 길이만 본다.
- 비용이 걸린 키가 필요한 기능은 서버를 거쳐 호출하는 구조로 바꾼다.
- 키는 URL 쿼리가 아니라 헤더로 보낸다. 쿼리는 서버 로그와 프록시에 남는다.

**Why:** 결제가 연결된 키가 새면 남이 쓴 만큼 청구된다. 테스터에게 앱을 나눠 줄 때 키를 뺀 빌드를 따로 만들어 배포했다.
