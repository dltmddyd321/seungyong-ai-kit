# 서버 API 연동 규칙

## 1. 사용자 동작 한 번에 서버 요청 한 번

사용자가 버튼을 한 번 누르면 서버 계산 요청도 한 번만 보낸다. 결과가 비었거나 마음에 들지 않는다고 조건(범위, 필터, 옵션)을 바꿔 자동으로 다시 요청하지 않는다.

- 여러 조건의 결과가 필요하면 한 요청에 옵션으로 함께 보내거나, 사용자가 조건을 바꿔 다시 누르게 한다(버튼, 안내 문구).
- 네트워크 실패 재시도는 별개다. 같은 조건으로, 횟수 제한을 두고 재시도한다.
- 실시간 동기화처럼 자동 요청 자체가 기능인 경우는 예외다. 이때도 사양에 명시된 경우만 해당한다.

**Why:** 결과가 비면 범위를 넓혀 자동 재계산하도록 짰다가 "어떤 조건으로 다시 볼지는 사용자가 결정한다"는 지적을 받았다. 자동 재요청은 서버 부하와 비용을 늘리고, 사용자가 본 결과가 어떤 조건에서 나왔는지 흐리게 만든다.

## 2. 연동 체크리스트는 같은 커밋에서 갱신한다

API 연동 작업을 할 때마다 연동 현황 문서(예: `docs/API_CHECKLIST.md`)를 같은 커밋에서 갱신한다.

| 표시 | 뜻 |
|---|---|
| ✅ | 화면 연결 + 실제 호출 확인 |
| 🔌 | 화면에 연결만 됨(실호출 미확인) |
| 🟡 | 클라이언트 인터페이스에만 등록 |
| ⬜ | 미등록 |
| ➖ | 이 앱에서는 쓰지 않음 |

- 상단에 상태별 개수와 갱신 날짜, 하단에 변경 기록을 둔다.
- 엔드포인트 목록의 근거는 서버의 Swagger/OpenAPI 명세다. 위키나 메신저에 정리된 표는 오래됐을 수 있으니 명세와 대조한다.
- 같은 서버를 쓰는 앱(저장소)이 여러 개면 각 저장소 문서를 모두 갱신한다.

**Why:** 문서를 나중에 몰아서 고치면 어떤 API가 실제로 확인됐는지 기억에 의존하게 된다. 같은 서버를 쓰는 두 앱의 현황이 어긋난 적도 있다.
