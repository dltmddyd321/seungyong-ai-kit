`{BASE_BRANCH}`는 프로젝트의 통합 브랜치(예: `dev`, `main`)로 바꿔서 설치한다.

## 수행 순서

**1. 이번 작업 내용 파악**

아래를 읽는다.
- `.claude/current_issue.md` (현재 이슈 정보, 있으면)
- `_workspace/04_review.md` (있으면, 리뷰 결과)
- `git diff {BASE_BRANCH}...HEAD --stat` (변경 파일 목록)

**2. 학습 가치 판단**

다음 중 하나라도 해당하면 스킬에 반영할 가치가 있다.
- 이번에 새로 알게 된 프로젝트 고유 패턴(특정 API 사용법, DB 사용 시 주의사항 등)
- 찾는 데 시간이 걸린 파일이나 구조. 다음에 빨리 찾을 수 있게.
- 같은 도메인(결제, 알림 등)에서 반복될 가능성이 있는 패턴
- Reviewer가 지적한 주의사항

학습 가치가 없으면(단순 문자열 수정 등) "학습할 내용 없음"을 출력하고 끝낸다.

**3. 스킬 업데이트**

변경된 파일의 도메인에 따라 해당 스킬에 추가한다.
- 도메인 전용 참조 스킬이 있는 영역(예: 결제) → 그 스킬의 `SKILL.md`
- 그 외 일반 → 프로젝트의 메인 개발 스킬(예: `android-dev`)의 에이전트 프롬프트에 주의사항 추가

추가 형식(스킬 파일 하단에 append):
```
## 학습된 패턴 ({이슈 키}, YYYY-MM-DD)
- {패턴 설명}: {구체적인 파일:라인 또는 코드 예시}
```

**4. 완료 메시지**
- 어떤 스킬의 어느 부분에 무엇을 추가했는지 출력한다.
- 추가하지 않았다면 이유를 출력한다.
